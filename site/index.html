TRAMA // motor de mapas de red

Tu red, viva en el navegador. Sin GIS. Sin lock-in.

Sube el modelo que ya tienes — EPANET, GeoJSON, OpenStreetMap — y en menos de un minuto lo ves simulado, con el tiempo como un vídeo. Es un archivo tuyo, no una cuenta en la nube de nadie: se comparte con un enlace, funciona sin internet y sale a formatos estándar cuando tú digas.

01 // por qué existe

Lo que hoy no puedes hacer

Las herramientas que simulan tu red cuestan de 6.000 a 15.000 € al año, por asiento y por dominio. Los formatos abiertos no tienen grafo; los motores de mapas no tienen tiempo. TRAMA une las piezas en un núcleo abierto bajo BSL 1.1.

formato

Tu red es un archivo

Hoy tu modelo vive preso en una licencia, en el PC del técnico que sabe usarla. Un .trama se abre en cualquier navegador, hasta en el móvil: se comparte con un enlace, se sirve desde cualquier CDN y funciona 100% offline.

render

El tiempo como eje

Un SIG enseña dónde están las tuberías. Ninguno enseña qué pasa dentro a las tres de la tarde. Aquí recorres 24 h de presiones o tráfico como un vídeo y vuelas en 3D por la red — fluido con cien mil tramos, medido, no prometido.

solvers

Un motor, todos los dominios

Cada dominio tiene hoy su silo de software. Aquí el contrato es uno: EPANET escribe presiones, un router escribe rutas, y «¿quién pierde servicio si corto aquí?» es la misma pregunta para una válvula que para una calle. SWMM y pandapower encajan sin tocar el núcleo.

03 // abierto de verdad

La especificación es pública. La salida, siempre libre.

Si TRAMA desapareciera mañana, tus datos se abren pasado mañana en cualquier GIS del mundo. Ese es el trato, y está medido.

  • Salida verificada — GeoJSON, GeoPackage y teselas MVT, comprobados con GDAL y lectores independientes, no con nuestra propia herramienta
  • BSL 1.1 en núcleo, formato y compilador — uso interno permitido; servicio alojado a terceros requiere licencia
  • Self-hosted primero — el cloud gestionado será opcional, nunca obligatorio
  • Registry de solvers comunitario con verificación y versionado
# solver.toml id = "epanet" version = "0.1.0" runtimes = ["wasm", "server"] # qué lee del grafo [inputs] edges = ["pipe", "valve", "pump"] props = ["diameter", "roughness"] # qué escribe en el estado [outputs] channels = ["pressure", "flow"]

04 // para developers

PMTiles lo hizo con los mapas. TRAMA lo hace con las redes.

Un archivo estático servido por HTTP range requests, sin servidor de tiles. La diferencia: dentro hay un grafo con IDs estables, propiedades tipadas y canales de estado que los solvers escriben en runtime — y un runtime TypeScript sin dependencias que lo pinta sobre MapLibre con eje temporal.

# hoy: clona y compila — todo el código es público git clone https://github.com/Neixen-labs/trama # al lanzamiento — la lista de espera avisa npm install @trama/core # runtime, 25 kB, cero dependencias # tu red, fuera, cuando quieras trama export red.trama salida/ --to geojson|gpkg|mvt
